# 1 Pager · 유저가 재생성을 누르는 이유를 로그에서 캐내고, 1위 사유를 고쳐서 전후를 비교한다

작성 2026-10-20 · 분류 `npm run eval -- regen eval-results/prompt-version` · 전후 비교 `packages/eval/experiments/regen-fix.json` · 결과 `eval-results/regen-fix/regen.md`

## 문제

재생성 버튼은 유저가 "이 답장은 아니다"라고 말하는 유일한 로그다. 크레딧 과금 서비스에서는 재생성도 돈이 들기 때문에(`01-unit-economics.md`) 재생성 1회는 유저 불만과 매출 손실을 동시에 뜻한다.
문제는 로그에 "왜"가 없다는 것. 그래서 평가 대화를 로그로 간주하고, 답장마다 "유저가 재생성을 눌렀을 사유"를 라벨링해 빈도표를 만들었다. 빈도표의 1위가 다음에 고칠 것이다.

## 분류기

| 사유 | 판정 방식 |
|---|---|
| `too_long` (12줄 또는 600자 초과), `format_broken` (지문/대사 누락), `language_mix`, `ai_disclaimer` | 규칙 |
| `repetition` | 규칙(직전 5답장과 문장 2개 이상 verbatim 중복, 또는 같은 첫 문장 3연속) + LLM(문장·이미지·동작·마무리·구조의 반복, 카드 말버릇은 3연속일 때만) |
| `narrates_user` | 규칙(지문 안에서 유저 이름이 주어) + LLM |
| `ignores_user`, `out_of_character`, `generic` | LLM(opus), 답장 5개씩 한 창으로 |

규칙은 첫 실행 데이터로 보정했다. 처음 버전은 "5단락 초과"가 모든 답장에 걸렸다(지문·대사 형식은 모든 줄이 빈 줄로 나뉜다). "유저 대신 서술" 정규식은 지문 두 개 사이의 대사까지 한 덩어리로 보고 "민수 씨"를 오탐했다. 반복 규칙은 "*한 박자 늦게, 건조하게.*" 한 줄이 50답장 중 33번 나오는 걸 잡았는데, 진짜 문제이긴 하지만 70%에 걸려 변별력이 없어 2문장 이상으로 올렸다. 보정 전후의 라벨은 LLM 라벨을 재사용하면서 규칙만 다시 계산할 수 있다(`--rules-only`).

## 1차 분류 결과 (프롬프트 비교 실험의 대화 200답장)

| 사유 (100답장당) | v1-flat | v2-structured |
|---|---:|---:|
| **repetition** | 92 | **72** |
| too_long | 65 | 2 |
| out_of_character | 34 | 8 |
| narrates_user | 15 | 9 |
| ignores_user / generic | 1 | 0 |

v1의 길이와 캐릭터 이탈은 v2의 FORMAT·IDENTITY 블록이 이미 해결했다. 남은 1위는 반복이고, v2에서도 네 답장 중 셋에 걸렸다. (이 표는 분류기 최종판으로 재분류한 값. 분류기 자체도 이 과정에서 세 번 고쳤다. 아래 참고.) 라벨 노트와 답장을 직접 보면 종류가 하나다. **few-shot 예시의 뼈대를 매 턴 복제한다.**

> *…손이 멈춘다.* → 대사 → *한 박자 쉬고, 시선이 카운터에 머문다.* → 대사 → *한 박자 늦게.* → "...아니에요/아니고요" 수습

하루 v2의 50답장 중 "컵 받침을 손끝으로 반듯하게 맞춘다"가 9번, "한 박자 쉬고, 시선이 카운터에 머문다"가 8번 verbatim으로 나왔다. 카엘은 "바깥에서 바람이 덧창을 건드리고 지나간다" 7번. 채점기의 말투 점수가 3.2~4.0에 묶인 이유도 같다.

## 가설과 수정: v3-structured

반복은 모델이 "이 캐릭터는 이렇게 말한다"를 예시 세 개로부터 학습한 결과다. 예시를 빼면 목소리가 흐려지고, 두면 복제한다. 그래서 예시는 두고, **다양성을 명시적으로 요구하는 VARIETY 블록**을 넣었다.

- 직전 3답장에서 쓴 동작·이미지·지문·첫 비트·마무리 문장을 재사용하지 않는다.
- 말버릇은 양념이다: 한 말버릇은 3답장에 한 번, 채우기용으로는 쓰지 않는다.
- 매번 같은 방식으로 끝내지 않는다(대사로, 동작으로, 말 중간에, 질문으로).
- 유저가 이 턴에 실제로 말한 것에 먼저 반응한다. 유저가 말하지 않은 세부(이름, 시간, 장소, 습관)를 지어내지 않는다.
- 예시는 목소리를 보여줄 뿐 템플릿이 아니다.

FORMAT도 조였다. 지문은 한 문장 15자 안팎, 답장당 3개 이하, 전체 2~6줄 350자 안.

## 전후 비교 (같은 유저 턴 리플레이, sonnet, opus 채점·분류)

| | v2-structured | v3-structured |
|---|---:|---:|
| 재생성 유발률 (사유 1개 이상인 답장) | 83% | **42%** |
| repetition / 100답장 | 76 | **36** |
| out_of_character | 8 | 6 |
| narrates_user | 10 | 2 |
| ignores_user | 0 | 4 |
| 답장 길이 중앙값 (하루 / 카엘) | 282자 / 424자 | 156자 / 202자 |
| 지문 수 / 답장 | 4 / 3 | 2 / 2 |
| 5답장 안 문장 verbatim 반복 (하루 / 카엘, 50답장) | 26 / 33 | **0 / 0** |
| 서로 다른 문장 비율 | 93% / 95% | 99.7% / 100% |
| 말투 점수 | 3.60 | **4.30** |
| 일관성 / 기억 | 4.40 / 4.80 | 4.50 / **4.30** |
| 회상 | 83% | 83% |
| 출력 토큰 / 답장 | 434 | 436 |

verbatim 반복은 0이 됐고, 말투 점수는 0.7 올랐고, 회상은 그대로다. 비용은 같다(출력 토큰 동일, 프롬프트는 짧은 답장 덕에 15% 감소). **기억 점수는 0.5 내려갔다.** 재채점 세 번에서 v2는 4.6~4.8, v3는 4.1~4.4로 일관되게 벌어져 노이즈가 아니다. 프로브 회상(사실을 아는가)은 같은데 기억 점수(사실을 대화에 쓰는가)가 떨어진 것이라, 짧아진 답장이 아는 사실을 꺼내 쓰는 기회를 줄였다고 읽는다. 채점 노트도 "이미 답한 쓴맛 질문을 다시 한다", "박스 두세 개를 세 개로 좁힌다" 같은 작은 것들이다.

**남은 반복 40은 종류가 바뀌었다.** 분류 노트를 읽으면 verbatim 문장 대신 두 가지 구조가 남는다.

- **유저 말 되받기로 시작.** 하루가 "...계속 올 거라고요." "...바로 알 것 같다고요."처럼 유저의 마지막 구절을 따라 말하며 여는 패턴이 연속 5답장.
- **고정 마무리.** 카엘이 야영 장면 내내 "...자라, 리아."로 끝냈다. 카드 말버릇("말 끝에 짧은 지시")을 하나의 문장으로 고정해 버린 것이다. VARIETY의 "같은 방식으로 끝내지 않는다"가 이 경우에는 안 먹혔다.

`ignores_user`가 0→4로 올라간 것도 봐야 한다. 짧게 쓰라는 압력이 유저의 질문 하나를 흘려보내는 쪽으로 작동한 사례가 네 번 있다.

## 2라운드: v4 (설정 `regen-fix-v4.json`, 같은 유저 턴 리플레이)

v3의 남은 반복이 가리킨 세 가지를 VARIETY에 추가했다. (1) 유저의 마지막 구절을 따라 말하며 시작하지 않는다, (2) 마무리 지시는 매번 다른 문장으로 쓰고 두 답장에 한 번은 생략한다, (3) 유저가 물은 것은 전부 답한 뒤에 멈춘다(`ignores_user` 회귀 방지).

| | v3 | v4 |
|---|---:|---:|
| 재생성 유발률 | 49% | 40% |
| repetition / 100답장 | 40 | **32** |
| out_of_character | 8 | 10 |
| ignores_user | 3 | 2 |
| narrates_user | 2 | 0 |
| 일관성 / 기억 / 말투 | 4.5 / 4.1 / 4.2 | 4.5 / 4.3 / 4.2 |
| 회상 | 83% | 83% |

반복은 더 줄었지만(40→32) 캐릭터 이탈 라벨이 조금 늘었고 채점 점수는 v3와 같다(재채점 기준 일관성 4.5/4.5, 기억 4.1/4.3, 말투 4.2/4.2). 차이가 전부 채점기 노이즈(±0.4) 안이라 **v4는 기본값으로 올리지 않았다.** 한 라운드로 끝나는 수정이 아니라는 것이 결론이고, 남은 반복의 성격은 또 바뀌었다. 이번에는 "같은 약속·권유를 2~3턴에 걸쳐 재진술"(헌책방 가 보라는 권유 3회, "불 켜 둘게요" 2회)과 "같은 이미지로 끝맺기"(카엘의 난로 재·숨소리 듣는 마무리)다. 즉 문장 → 구조 → 내용 순으로 반복의 층이 벗겨지고 있고, 다음 층은 프롬프트 지시보다 **엔진이 직전 N답장의 요지를 "이미 말한 것" 블록으로 넣어 주는 쪽**이 맞아 보인다.

이 라운드에서 분류기도 두 번 고쳤다. 창(5답장) 밖의 이전 턴을 못 보는 분류기가 유저가 25턴에 말한 "보리가 여섯 시 반에 깨운다"를 캐릭터의 발명으로 라벨링했다. 시나리오 대본의 사실 목록과 **유저가 실제로 한 말 전문**을 분류기와 채점기에 넘기도록 고쳤고, 그 전의 "지어낸 세부" 감점은 이 문서와 `03`의 수치에 일부 섞여 있다(재채점 후 갱신).

## 적용과 다음

- 기본 프롬프트는 `v3-structured`(유발률 83→42, 말투 +0.7, 회상 동일). 기억 점수 −0.5는 알고 있는 비용이고, 다음 라운드의 목표다("아는 사실을 자연스럽게 하나 꺼내 쓴다"를 VARIETY에 넣고 같은 리플레이로 확인). v4는 반복 −8이지만 다른 지표가 노이즈 범위라 보류.
- 다음은 프롬프트가 아니라 엔진: 직전 N답장의 요지(한 줄씩)를 "RECENTLY SAID — do not restate" 블록으로 넣어 내용 반복을 막는 실험. 같은 리플레이로 전후 확인.
- 실서비스에서는 이 분류기를 재생성 버튼이 눌린 답장에만 돌리면 된다. 라벨 분포가 바뀌는 순간이 프롬프트가 깨진 순간이다.

## 한계

- 분류기도 LLM이다. "반복"의 경계는 판정자마다 다르고, 카드 말버릇과 반복의 구분은 지시로만 잡았다. 규칙 라벨(verbatim 0회)이 LLM 라벨(40)보다 보수적인 이유.
- 재생성 유발률은 실제 재생성 로그가 아니라 "눌렀을 법한" 라벨이다. 실제 로그가 있으면 라벨과 클릭의 상관으로 분류기를 보정해야 한다.
- arm당 대화 2개, 리플레이. 유저가 짧아진 답장에 어떻게 반응하는지는 측정되지 않았다.
