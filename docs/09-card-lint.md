# 1 Pager · 채점기가 400턴 내내 같은 말을 했다: 캐릭터 카드가 자기 예시와 모순될 때

작성 2026-10-21 · 측정 스크립트 없음(저장된 대화 JSON의 지문 길이 집계) · 재채점 `eval-results/card-fix-rejudge` · 재생성 `packages/eval/experiments/card-fix.json` · 린트 `npm run lint-cards`

## 관찰

200턴 장기 실행(`02`)에서 말투 점수가 20개 체크포인트 전부 **4.0**이었다. 일관성은 4.9, 기억은 4.7인데 말투만 한 번도 5가 안 됐다. 채점 메모를 모아 보니 20개 중 20개가 같은 지적이었다.

> "Several 지문 run well over 15자, e.g. '…'" (턴 20) · "Stage directions often exceed ~15자" (턴 260) · "Several stage directions exceed ~15 characters" (턴 340)

같은 지적이 v5 대화(`regen-fix-v6`, 하루 2대화)에서도 체크포인트 10개 중 10개에 있었다. 프롬프트 버전 세 개를 바꿨는데 이 지적만 꿈쩍하지 않았다.

## 측정

저장된 하루 대화 전부에서 `*…*` 지문의 글자 수를 셌다.

| 실행 | 프롬프트 | 지문 n | 중앙값 | p90 | 20자 초과 |
|---|---|---:|---:|---:|---:|
| prompt-version | v1-flat | 319 | 28 | 53 | 62% |
| prompt-version | v2-structured | 221 | 23 | 37 | 62% |
| regen-fix | v3-structured | 101 | 22 | 29 | 72% |
| regen-fix-v6 | v4-structured | 203 | 21 | 28 | 58% |
| regen-fix-v6 | v5-structured | 204 | 24 | 30 | 75% |
| long-run (400턴) | v3-structured | 433 | 24 | 32 | 76% |

v1→v3에서 꼬리(p90 53→29)는 잘렸지만 중앙값은 다섯 버전 모두 21~24자다. 프롬프트의 FORMAT 블록은 v3부터 "about 15 characters"라고 쓰는데, 모델은 다른 것을 따르고 있었다.

## 원인

하루 카드의 `style.ko.quirks`에 "지문은 한 줄, **15자 안팎**"이 있다. 같은 카드의 `style.ko.examples`에 있는 지문 세 개는 **26, 27, 35자**다. 일본어 블록도 같다(규칙 15文字, 예시 22~30자).

모델은 규칙보다 예시를 복제한다(`04`에서 few-shot 예시의 문장 뼈대가 매 턴 복제되는 것을 봤다). 채점기는 규칙을 읽고 집행한다. 둘 다 자기 일을 했고, 카드가 모순이었다. 결과는 세 가지다.

- 말투 점수에 **천장**이 생긴다. 체크포인트마다 이 지적이 들어가니 5가 나올 수 없고, 다른 말투 문제는 메모에서 밀려나 보이지 않는다.
- 프롬프트 라운드가 헛돈다. 지문 길이는 어느 버전으로도 안 움직였고, 움직일 이유도 없었다.
- 재생성 라벨 `too_long`과도 무관하다(600자/12줄 기준). 지문 하나가 25자인 것은 유저가 재생성을 누를 이유가 아니다.

## 수정

규칙을 예시에 맞췄다. "15자 안팎" → "25자 안팎(아래 예시 길이)". 예시를 15자로 줄이는 쪽은 택하지 않았다. 카드의 예시("창밖을 잠깐 보고, 다시 {{user}}의 어깨로 시선이 간다.")가 캐릭터의 의도된 호흡이고, 15자("컵을 닦는다.")는 너무 짧아 지문이 할 일(감정을 행동으로 보여주기)을 못 한다.

## 검증 1 · 같은 대화를 고친 카드로 재채점

`regen-fix-v6`의 v5 대화 4개(하루 2, 카엘 2)를 그대로 두고 채점기만 다시 돌렸다. 카엘 카드는 건드리지 않았으니 카엘 두 대화의 변화가 **채점기 노이즈 기준선**이다.

| 대화 | 말투 전 | 말투 후 | 지문 길이를 지적한 창 (전 → 후) |
|---|---:|---:|---|
| 하루 r0 | 4.0 | 4.4 | 5/5 → 0/5 |
| 하루 r1 | 4.0 | 4.0 | 5/5 → 1/5 |
| 카엘 r0 (대조) | 4.2 | 4.6 | – |
| 카엘 r1 (대조) | 4.6 | 4.6 | – |

지적은 사라졌다(10/10 → 1/10). 점수는 하루 평균 +0.2, 대조군 카엘도 +0.2 움직였다. 즉 **점수로는 수정 효과를 분리할 수 없다**(채점기 노이즈 ±0.4, `02`의 한계 절). 메모 내용으로만 확인된다. 지적이 빠진 자리에는 다른 것이 들어왔다: "턴 16이 질문으로 끝나고 감정을 직접 말함('다행이에요')", "농담 뒤 수습이 억지스러움". 이것들이 다음 라운드의 재료다. 천장 하나를 치우니 그 아래 문제가 보인다.

## 검증 2 · 고친 카드로 재생성

`card-fix.json`: v5, 하루·카엘, 2반복, `regen-fix-v4` 유저 턴 리플레이. 카드의 quirk 문장이 프롬프트에 들어가므로 생성 쪽도 바뀔 수 있다.

| | 기존 v5 (`regen-fix-v6`, 옛 카드) | 고친 카드 (`card-fix`) |
|---|---:|---:|
| 하루 지문 중앙값 / p90 / 20자 초과 | 24 / 30 / 75% | 23 / 30 / 71% |
| 카엘 지문 중앙값 (대조, 카드 불변) | 40 | 36 |
| 하루 말투 (2대화) | 4.0, 4.0 | 4.0, 4.0 |
| 카엘 말투 (대조) | 4.2, 4.6 | 4.6, 4.6 |
| 전체 일관성 / 기억 / 형식 | 4.55 / 4.55 / 5.00 | 4.55 / 4.45 / 5.00 |
| 회상 | 83% | 83% |
| 재생성 유발률 / 반복(100답장당) | 30% / 24.5 | 27% / 20.0 |
| 하루 창에서 "15자" 지적 | 10/10 | **0/10** |

예상대로 생성 쪽은 안 바뀌었다. 지문 길이는 카드가 15자라고 하든 25자라고 하든 23~24자다(모델은 예시를 따른다). 말투 점수도 4.0 그대로다. 바뀐 것은 **채점 메모의 내용**이다. "15자를 넘는다"가 사라진 자리에 들어온 지적을 하루 2대화 10개 창에서 세어 보면:

| 새로 보이는 말투 문제 | 창 수 |
|---|---:|
| 문장 끝이 반말로 흐름 ("켜 두길 잘했다", "넣은 거니까.", "정할 일이고") | 4 |
| 관찰 대신 질문으로 끝남 (카드: "질문보다 관찰을 말한다") | 2 |
| 감정을 직접 말함 / 상담사 말투 ("좀 어색해요", "꽤 걸리는 일이겠네요") | 4 |
| "...아," / "음," 오프너가 드묾 | 3 |
| 지문이 두 문장 또는 한 줄 초과 | 3 |

하루의 말투가 4.0에 머무는 진짜 이유는 지문 길이가 아니라 **존댓말 끝맺음이 반말로 새는 것과 관찰 대신 질문으로 끝나는 습관**이었다. 세 라운드 동안 같은 지적 하나가 메모를 채우고 있어서 보이지 않던 것이다. 이 둘이 다음 프롬프트 라운드(v6)의 목표가 된다. 측정 가능한 규칙으로 바꿀 수 있다: 대사 마지막 문장의 어미가 "~다/~고/~니까"로 끝나는 비율, 대사가 "?"로 끝나는 비율.

## 도구로 남긴 것 · `npm run lint-cards`

같은 실수를 다음 카드에서 LLM 호출 없이 잡는 린트. 카드 하나를 1초에 검사한다.

| 규칙 | 잡는 것 |
|---|---|
| `action-length-vs-examples` | quirks의 숫자 길이 규칙("N자 안팎", "N文字前後", "about N characters")과 예시 지문의 중앙값이 30% 이상 어긋남 |
| `quote-convention` | 일본어 예시·첫 메시지에 ASCII `"…"` (「」가 규칙, `06`의 따옴표 표류) |
| `example-format` | 예시 답장에 지문 또는 대사가 없음 |
| `avoid-in-examples` | avoid 목록의 인용 토큰("ㅋㅋ" 등)이 예시에 등장 |
| `narrates-user` | 예시가 유저의 행동·대사를 씀 |
| `missing-first-message` | style 블록은 있는데 그 언어의 첫 메시지가 없음 |

고치기 전 카드에 돌리면 `haru/ko`, `haru/ja` 두 건이 error로 잡힌다. 지금은 0건.

## 한계

- 채점기 노이즈가 수정 효과(+0.2)보다 크다. 이 문서의 근거는 점수가 아니라 **메모의 내용 변화**(10/10 → 1/10)다.
- FORMAT 블록의 "about 15 characters"는 모든 캐릭터에 공통으로 박힌 숫자다. 카엘 카드는 "한두 줄"이라고만 하고, 하루는 이제 25자다. 다음 프롬프트 버전에서 숫자를 빼고 카드의 예시 길이를 따르게 할 것. 모델이 이 숫자를 어차피 무시했으므로(위 표) 생성 결과는 안 바뀔 것으로 예상하지만, 안 지키는 규칙은 프롬프트에서 빼는 게 맞다.
- 린트는 카드 안의 모순만 본다. 카드와 프롬프트 사이의 모순(위 FORMAT 숫자)은 못 잡는다.
