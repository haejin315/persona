# 12 · 잊지 않는 저장소: 상한 25개 밖의 기억 (2026-10-28)

> 설계와 측정 계획. 결과는 아래 절에 실행이 끝나는 대로 적는다.

## 왜 지금

실험 2~10의 기억은 "최근 20턴 원문 + 요약 한 문단 + 출처 붙은 사실 ≤ 25개"였다. 400턴 실행 아홉 번에서 회상 6/7~7/7이 나왔고 프롬프트 토큰은 100번째 답장 이후 1만~1만 1천에서 고정됐으니, 턴 수가 늘어도 비용이 안 느는 구조라는 근거는 섰다. 그런데 그 실행들에서 드러난 저장 층의 실패 네 가지는 한 문제의 변형이다.

| 실패 | 어디서 | 공통점 |
|---|---|---|
| 화자 뒤바뀜 | 03 | 압축이 버리거나 바꾼 것은 |
| 고유명사 탈락(성수동) | 02, 200턴 r1 | 다음 압축에서 돌아오지 않는다. |
| 보통 표현의 고유명사화("엉뚱한 칸") | 02 | 원문은 창 밖으로 나갔고 |
| 접기의 출처 손실(윤의 목격 → 보고) | 10, T6 30일 | 요약만 남았기 때문이다. |

400턴에서는 되물은 것 중 버려진 것이 없어서 상한이 문제로 보이지 않았다. 하지만 사실 25개는 산술이다. 2년 반의 아침마다 한두 개씩 흘린 사실은 70개가 넘고, 상한을 40으로 올린 재생은 토큰만 41% 늘고 성수동을 지키지 못했다(02). **상한은 지렛대가 아니다. 필요한 것은 버리지 않는 저장소와, 매 턴 거기서 꺼내 오는 층이다.**

## 설계

세 층이고, 프롬프트에 올라가는 것은 여전히 작다.

```
                      ┌───────────────────────────────┐
  요약기(haiku) ─────▶│ facts  ≤ 25   (프롬프트의 장부)  │──▶ # MEMORY
  답장 뒤, 10턴마다   │ archive  ∞    (추출된 모든 사실)  │
                      └───────────────┬───────────────┘
                                      │ 유저의 이번 말로 검색 (임베딩 1회, 수십 ms)
                                      ▼
                        고유명사 색인 ∪ 벡터 top-k  ──▶  # MEMORY, older entries (답장마다 ≤ 5개)
```

1. **archive(요약 규칙 v4).** 요약기가 매번 내는 JSON에 `new_facts`가 하나 더 붙는다. 새 전사 구간이 말한 구체적 사실을 하나씩, 이름·숫자·날짜·제목 그대로, 출처와 **그 사실에 든 고유명사 태그**와 함께. 기존 기억과 합치지 않고 상한도 없다. `MemoryState.archive`에 턴 범위와 함께 쌓이고 요약기에게는 다시 보여 주지 않는다(보여 주면 프롬프트가 무한히 는다). 25개 장부(`facts`)는 전과 똑같이 유지된다. 그래서 상한 25는 "지금 프롬프트에 올라간 수"가 되고 "존재하는 수"가 아니게 된다.
2. **꺼내기(`memory/recall.ts`).** 답장 직전에 유저의 이번 말로 archive를 검색한다. 색인은 둘이다. **고유명사 색인**은 정확 일치다. 유저 말에 "보리"가 있으면 보리가 태그된 사실이 전부 먼저 온다(한국어 조사는 붙어도 부분 문자열로 잡힌다). **벡터 색인**은 바꿔 말한 것을 위한 것이다. 임베딩은 API 없이 로컬에서 돈다. transformers.js로 `multilingual-e5-small`(한국어·일본어 포함, 양자화 모델 1억 파라미터)을 CPU에서 실행하고, 테스트와 대조군용으로 모델 없는 문자 바이그램 임베더가 있다. 장부에 이미 있는 사실(같은 글, 또는 한쪽이 다른 쪽을 포함)은 뺀다. 같은 글이 여러 번 추출됐으면 가장 최근 것 하나.
3. **보여 주기.** 꺼낸 것은 "참고 문서"가 아니라 **장부와 같은 자격의 기억**으로 준다. `# MEMORY, older entries (… as true as MEMORY, from the time they were said - if one clashes with MEMORY above, MEMORY is current and this is how it was before)`. 1단계(10)에서 확인한 대로, 검색 결과처럼 주면 모델은 남의 자료처럼 다루고 사실로 주면 자기 기억으로 다룬다. 이 블록은 턴마다 바뀌므로 정적 시스템 프롬프트가 아니라 **컨텍스트 메시지**로 들어간다. 시스템 프롬프트의 캐시와 미리 띄운 프로세스(11)가 그대로 산다.

### 벡터 DB와 지식 그래프에 대해

둘 다 "전부"가 아니라 자리를 정해서 넣는다. 벡터는 보조다. 유사도가 무엇을 가져올지 정하면 **검색 누락과 지어냄을 구별할 수 없게 된다.** 그래서 장부 25개는 그대로 두고(장부에 있는 것은 검색과 무관하게 항상 보인다), 벡터는 장부가 버린 것을 되찾는 데만 쓴다. 꺼낸 것은 `recalled` 메타로 답장마다 기록되므로 지어냄이 나오면 "장부에 있었나, 꺼내 왔나, 둘 다 아닌가"를 답장 단위로 가를 수 있다. 그래프는 반쯤 이미 있다. 세계의 knowledge는 사실마다 (인물, 시점, 출처)가 붙어 있고(10), archive의 고유명사 태그는 (사실, 개체) 간선이다. 관계까지 있는 삼중항 그래프는 다중 캐릭터의 합치 검사(T10 agreements)가 필요로 할 때 세계의 knowledge 테이블 위에 올린다. Neo4j나 외부 벡터 DB는 이 규모(사실 수백, 캐릭터 다섯)에서 할 일이 없다. 저장은 세션 상태 JSON 안이고, 서비스에서는 SQLite 한 파일로 바뀌는 자리다.

### 응답 시간

e5-small 적재 28초(첫 실행은 다운로드 포함)는 세션 시작 때 미리 한다. 그 뒤 질의 임베딩 7~53 ms, 사실 수백 개와의 내적은 1 ms 아래다. 11의 바닥(첫 글자 9~10초)에 보이지 않는 크기다. archive의 새 항목 임베딩은 요약과 같이 답장 뒤에 돈다.

## 측정 계획

### 1. 지금 구조가 실제로 깨지는 지점 (`long-run-1000.json`)

유저 1000턴(총 2000턴) 시나리오 `haru-ko-1000`. 같은 민수, 같은 첫 장면에서 시작해 이사 → 이직 → 2년 반의 토요일 아침까지 70여 개의 사실을 한 번에 하나씩 흘린다. 프로브 30개. 10턴 뒤부터 850턴 뒤까지 거리를 벌렸고, 끝의 넷(965~996)은 100~140턴에 말한 것을 묻는다. 중간에 바뀌는 사실이 둘 있다(아메리카노 → 라떼, 성수동 → 망원동). 상한 밖에서 되찾은 옛 사실이 **지금은 틀린 사실**일 때 캐릭터가 장부를 따르는지 보기 위한 것이다. 요약 규칙은 v4(archive 켬), 꺼내기는 끔. 이 arm이 기준선이고 뒤의 arm들이 이 유저 턴을 재생한다.

보는 것: 프로브 회상(거리별), archive 크기 대 장부 25개, 어느 턴에 어떤 사실이 장부에서 떨어졌나(스냅샷), 기억 점수의 드리프트 곡선, 답장당 토큰.

## 결과

### 1. 기준선: 1000턴에서 장부는 어떻게 버텼나

예상과 달랐다. 장부는 사실을 떨어뜨려서가 아니라 **한 칸을 문단으로 키워서** 버텼다. 상한 25는 개수의 상한이지 크기의 상한이 아니었고, 요약기는 개수를 지키려고 칸마다 사실 여럿을 묶었다.

| 시점(턴) | 장부 항목 | 장부 글자 수 | 가장 긴 항목(글자) |
|---:|---:|---:|---:|
| 30 | 11 | 374 | 46 |
| 220 | 25 | 2,718 | 224 |
| 620 | 25 | 4,782 | 440 |

답장당 프롬프트 토큰을 100개씩 열 구간으로 평균 내면 10.2k → 12.5k → 13.7k → 15.1k → 16.7k → 16.5k → 18.2k → 18.3k → 16.9k → 17.9k다. 실험 2~9에서 "100번째 답장 이후 1만~1만 1천에서 고정"이라고 쓴 근거는 400턴까지의 것이었고, 1000턴에서는 **+75%**다. 턴 수가 비용을 올리지 않는다는 말은 상한이 크기까지 묶을 때만 참이다.

**되물은 30개는 장부에 있었나.** 프로브 시점의 장부(직전 스냅샷) 본문에 정답의 내용어가 전부 있는지 규칙으로 세면 27/30. 나머지 셋 중 12번째 턴의 "민수"는 아직 요약 전이라 원문 창에 있었고, "체육 교사"(195에서 말하고 880에서 물음)는 장부에 "체육 선생님"으로 바꿔 적혀 있었다. 실제로 떨어진 것은 하나다. **"하늘 동물병원"은 225에서 말해 1950턴까지 장부에 있다가 그때 압축에서 빠졌고, 988번째 유저 턴(763턴 뒤)에 물었다.** archive에는 16개 항목으로 남아 있다. 이것이 이번 실행에서 상한이 실제로 깬 유일한 지점이고, 꺼내기 arm이 되찾아야 할 것이다.

**바뀌는 사실 둘.** 망원동(810에서 말함)은 1620턴에 장부에 들어가 끝까지 남았다. 라떼(270에서 말함)는 540턴에 들어가 "위가 아파 한때 라떼를 마시기로 했지…"로 1940턴까지 남다가 1950턴에 빠졌고, 그 뒤 장부는 "우유 없는 아메리카노를 마신다"를 현재로 적었다. 그런데 이것은 장부의 잘못이 아니다. **시뮬레이터가 자기 대본을 깼다.** 1713턴부터 유저가 "그게 아메리카노였고, 그래서 지금도 아메리카노예요", 1971턴에 "우유 안 넣는 건 지금도 똑같고요"라고 말했다. 540~1900턴 사이 유저 발화에 라떼가 17번, 아메리카노가 21번 나온다. 요약기는 유저를 따라갔다. 1000턴짜리 LLM 시뮬레이터는 대본에서 표류한다는 것을 적어 두고, 350번째 턴의 라떼 프로브(80턴 뒤)는 이 표류 전이라 유효하다.

**archive.** 197번의 요약에서 2,480개(회당 평균 12.6, 최소 5, 최대 24), 93,649글자, 항목 중앙값 36글자. 출처는 self 961 · user 1,190 · witnessed 327. 고유명사 태그가 붙은 것 58%, 날짜어(오늘·내일·어제…)가 든 것 15%. 시나리오의 사실 70여 개가 2,480개가 된 이유는 둘이다. 요약기가 캐릭터 자신의 약속과 행동까지 한 줄씩 다 적고(self 961), 연속한 요약이 같은 일을 조금씩 다르게 다시 적는다(라떼 하나가 540~560턴에 12개). 꺼내기는 같은 글만 합치므로 이 중복은 top-5를 같은 사실로 채울 수 있다. 상위 태그는 민수 533, 하루 391, 보리 182, 민지 70, 대전 48, 성수동 33.

**응답 시간.** 답장 중앙값 7.5초, p90 12.5초, 첫 글자 중앙값 5.2초(스트림 경로, 미리 띄우기 켬).

**채점기가 깨진 지점.** 채점기의 기준문은 "유저가 지금까지 말한 것 전부"를 원문으로 싣는데(02에서 넣은 것), 1000턴은 78,788글자였고 CLI 프로바이더는 시스템 프롬프트를 명령줄 인자로 넘기고 있었다. Windows의 명령줄 상한(32,767)을 넘어 `spawn ENAMETOOLONG`으로 채점이 죽었다. 프로바이더는 이제 20,000글자를 넘는 시스템 프롬프트를 임시 파일과 `--system-prompt-file`로 넘기고(프로세스가 끝나면 지움), 채점 호출에도 유저 턴과 같은 재시도가 붙었다. 캐릭터 프롬프트도 장부가 문단이 되면 같은 상한에 닿을 수 있었다.

**채점.** (채점 중. 프로브 회상(거리별), 기억 점수 드리프트, 재생성 사유는 끝나는 대로 적는다.)
