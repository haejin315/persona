# 14. Graph RAG 기억 — 벡터 DB · 지식 그래프 · 청킹을 제대로 붙이고 다시 재기

## 요구

12·13의 꺼내기는 프로세스 안 배열과 SQLite 한 파일로 벡터 DB와 그래프의 역할을 대신했다. 그것은 "이 규모에서는 필요 없다"는 판단이었지, 요구가 아니었다. 요구는 처음부터 **모든 지식을 벡터 DB와 그래프 지식으로 저장하고 거기서 꺼내는 것**이었고, 그 구성이 1,000턴에서 어떤 점수를 내는지를 같은 자로 재는 것이다. 이 문서는 그 구성을 외부 저장소로 실제로 붙이고(Qdrant, Neo4j), 전사를 청킹해서 임베딩하고, 그래프를 단어(개체) 단위 삼중항으로 만들고, 같은 1,000턴 유저 턴을 재생해 잰 기록이다.

## 구성

```
                     ┌──────────────── 요약기(haiku, 10턴마다) ───────────────┐
  전사(turns) ──┬──► 사실 목록(10칸·1,000자, 프롬프트)                          │
               │    new_facts: 사실 한 줄 + 고유명사 태그 + triple(주어·관계·목적어) │
               │                                   │                         │
               │                        ┌──────────┴──────────┐              │
               │                        ▼                     ▼              │
               │                  Qdrant `facts`         Neo4j (:Entity)-[:REL]->(:Entity)
               │                  (e5 384차원, HNSW)      rel·text·turnFrom·turnTo·current
               └──► 청킹: 2교환(4턴) 창, 1교환 겹침 ──► Qdrant `chunks`
                                                                     ▲
  유저의 이번 말 ──► 개체 링크(그래프 노드 이름이 말에 있으면 seed) ──► 1~2홉 이웃 (edges ≤ 12)
                 ──► e5 query 임베딩 ──► chunks top-3, facts top-5 (최근 창 제외)
                 ──► 블록 하나: KNOWLEDGE GRAPH / RELATED FACTS / RELATED PAST EXCHANGES
```

- **벡터 DB: Qdrant** (`docker-compose.yml`, v1.13, HNSW, 코사인, `turnTo` 페이로드 색인). 컬렉션은 대화(namespace)마다 `<ns>-chunks`, `<ns>-facts`. 클라이언트 `@qdrant/js-client-rest`. `memory/vectordb.ts`의 `VectorIndex` 인터페이스 뒤에 있고, 테스트는 같은 인터페이스의 메모리 구현을 쓴다.
- **청킹** (`memory/chunker.ts`): 전사를 2교환(유저+캐릭터 4턴) 창으로, 1교환씩 겹쳐 자른다. 창은 0턴부터 고정 격자라 같은 턴은 항상 같은 청크 id가 되고(idempotent upsert), 창의 마지막 턴이 요약 창 밖으로 나가는 순간 한 번만 만들어진다. 청크 1개 ≈ 400~600자. 1,000턴(2,001 전사 턴) = 999청크.
- **임베딩**: multilingual-e5-small, transformers.js 로컬(12와 같음). 청크는 "passage: ", 질의는 "query: ".
- **그래프 DB: Neo4j** 5.26 community (`memory/graphdb.ts`). 노드 `(:Entity {ns, name})`는 **개체·개념 단어 하나**(민수, 보리, 하늘 동물병원, 아메리카노, 성수동, 스튜디오 합류). 간선 `[:REL {rel, text, turnFrom, turnTo, current}]`는 요약기가 사실마다 적은 삼중항. **같은 주어·같은 관계의 새 목적어가 오면 옛 간선은 `current: false`** (민수 —마신다→ 아메리카노 → 라떼). 호칭("하루 씨")은 벗겨서 노드 하나로. 질의는 가변 길이 경로 `(seed)-[:REL*1..2]-(x)`, 깊이·최신순, 상한 12.
- **삼중항 추출**: 요약 규칙 **v5** = v4 + 각 new_fact에 `"triple": {subject, relation, object}`. 주어·목적어는 개체 하나(문장 금지), 관계는 짧은 동사구, 변화는 같은 주어·관계에 새 목적어로. 판단은 모델, 저장과 supersede 표시는 저장소.
- **검색** (`memory/graphrag.ts`, `GraphRag.retrieve`): ① 개체 링크 = 그래프 노드 이름이 유저 말에 글자 그대로 있으면 seed(두 화자 이름은 seed 제외. 모든 간선에 닿아서). ② seed의 1~2홉 이웃. ③ 질의 임베딩으로 chunks top-3, facts top-5, `turnTo ≤ 요약 창 경계`로 프롬프트에 이미 있는 최근 턴 제외. ④ `renderGraphRag`가 블록 하나로, 줄마다 "[about N exchanges ago]", 바뀐 간선은 "(no longer)".
- **세션** (`SessionOptions.graphRag`): 요약 뒤(유저 경로 밖)에 새 사실을 facts 컬렉션과 그래프에, 요약 창을 막 벗어난 턴의 청크를 chunks 컬렉션에 넣는다. 답장 전에 retrieve → 컨텍스트 메시지 하나(시스템 프롬프트·캐시·prewarm은 그대로). 답장 meta에 `retrieval {seeds, edges, facts, chunks, ms}`와 `recalled[]`(why: graph | vector | chunk). restore 시 두 저장소를 비우고 스냅샷에서 다시 넣는다(체크포인트 재개).

## 실험 (`long-run-1000-graphrag.json`)

같은 유저 턴(long-run-1000) 재생, 사실 목록은 10칸·1,000자(13의 구멍 있는 조건), 요약 규칙 v5, 채점 opus.

| arm | 저장소 | 보이는 것 |
|---|---|---|
| ① `v13-ledger25` (12 기준선) | 없음 | 25칸 목록만 |
| ② `v13-ledger10-1000c` (13 B) | 없음 | 10칸·1,000자 목록만 |
| ③ `v13-ledger10-vector` | Qdrant | ② + chunks top-3 · facts top-5 |
| ④ `v13-ledger10-graphrag` | Qdrant + Neo4j | ③ + 그래프 1~2홉 이웃 ≤ 12 |

읽는 법: ②가 ①보다 프로브를 잃어야 구멍이 있는 것. ③−②가 벡터 DB(청킹 포함)의 값, ④−③이 그래프의 값. 기억·일관성·이탈·프로브, 그리고 retrieval meta로 턴당 블록 크기, seed가 선 횟수, 프로브 정답이 블록 안에 있던 비율, 첫 글자 시간을 센다.

**러너 스모크(24턴, 두 arm, 실제 저장소 + haiku 요약기):** 요약기는 사실 30개 중 24개에 삼중항을 달았다(민수 —마신다→ 아메리카노, 민수 —일한다→ 디자인 회사). 그런데 "오늘 —날씨→ 비", "버스 —밀렸다→ 비", "민수 —늦게 왔다→ 십 분"도 달았고, 그래서 "오늘"이 seed가 되어 24턴 중 6턴에 그래프가 섰다. 시간어는 거의 모든 말에 있으니 그대로 두면 12의 이름 잡음이 노드로 돌아온다. 둘로 막았다. 요약기 프롬프트에 "노드는 나중에 물어볼 수 있는 것, 시간어·날씨·수량·동작은 노드가 아니고 그런 사실에는 삼중항이 없다"(판단은 모델), 그리고 **허브 제외**: 전체 간선의 10%(하한 10개)를 넘게 닿는 노드는 seed가 되지 않는다(통계, 단어 목록 아님. 두 화자도 여기 걸린다). 검색 중앙값 38~42ms.

기록이 말하는 것 — 왜 ④가 ①이 아닌가.
- **(a) 사실 벡터의 87%가 하루 자신의 말.** 벡터 사실 hit 4,925개 중 4,284개가 "하루는 …"(source self; archive의 36%). 유저 질문 임베딩이 하루 문장 쪽에 더 가깝다. t105 "본가가 어디라고 했는지" → top-5 전부 하루의 약속. archive에 "민수는 이사 전 대전 본가에…"가 6개 있었는데 못 꺼냈다. t980 데미안(archive 12개)도 같다. 두 프로브를 ③④ 모두 놓쳤다.
- **(b) 2홉이 허브를 지나면 최신순 노이즈.** 그래프 줄 7,106개 중 깊이 2가 3,542개(50%). 경로가 허브(민수 간선 628, 하루 447)를 지나면 그 허브의 모든 간선이 후보가 되고, 최신순 12개를 자르니 seed와 무관한 최근 간선이 들어온다. t996: seed 만화 → "민수 —그렸다→ 만화"(깊이 1) → 민수의 최근 간선 11개(창가 자리, 아메리카노…). "민수 —그렸다→ 달빛 고양이"(280턴)는 같은 2홉인데 오래돼서 잘렸다. 허브 제외는 seed만 막았지 경로 통과는 안 막았다.
- **(c) seed 1위가 토요일**(1,000턴 중 199턴). 프롬프트 규칙에도 요약기는 "토요일"을 노드로 8번, "토요일 컵"·"토요일 약속" 같은 구를 20여 개 만들었다. degree 8은 허브 하한 10 아래. 그 199턴에 (b)의 노이즈 12줄이 붙었다.
- **(d) "(no longer)" 897줄**(그래프 줄의 13%). 같은 주어·관계에 다른 목적어 = 변화라는 규칙이 틀리는 경우가 많다: "민수 그렸다 만화 (no longer)"(달빛 고양이가 뒤에 와서), 약속했다 X / 약속했다 Y, 합격했다. 맞는 경우도 있다(이사한다 성수동 → 망원동, 마신다). 변화인지는 이야기에 대한 판단이지 단어 규칙이 아니다 — 10-27 원칙대로 모델에게 넘겨야 했다.

### 5차: 질의 (`long-run-1000-graphrag5.json`)

996과 816이 가리키는 것은 둘 다 **무엇을 질의로 삼느냐**다. 저장소와 블록은 ⑩ 그대로.

- **말한 문장이 질의** (`query: "sentences"`). `speechOf`가 `*지문*`을 떼고, `speechSentences`가 따옴표를 벗기고 문장으로 나눈다. 문장마다 임베딩해 청크·사실·간선 후보를 각각 검색하고, 한 점의 점수는 문장들 중 최대값(max fusion). 메시지 전체 한 벡터(1~4차)는 `"message"`, 지문만 뺀 한 벡터는 `"speech"`. 임베딩은 한 배치라 비용은 토큰 수에 비례해 비슷하고, 검색은 문장 수 × 4회.
- **이어받기** (`carry: 1`). 캐릭터 자신의 직전 답장도 그래프 seed에 넣는다(벡터 질의는 유저 말 그대로). 하루가 "병원 이름"을 꺼냈으면 다음 턴 블록에 `보리 —다닌다→ 하늘 동물병원`이 온다.
