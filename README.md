# persona

AI 캐릭터 채팅 엔진 + 평가 파이프라인. "캐릭터가 천 번째 턴에서도 살아있는가"를 감이 아니라 숫자로 확인하는 것이 목표.

캐릭터 채팅 서비스가 실제로 겪는 문제 여섯 개를 골라, 각각을 **재현할 수 있는 지표로 바꾸고 → 가설을 세우고 → 같은 유저 대본으로 arm을 비교하고 → 결과를 프롬프트/엔진에 적용**했다. 모든 실험은 이 저장소의 명령 한 줄로 다시 돌릴 수 있다.

전제가 되는 비용 분석은 [01 · 유닛 이코노믹스](docs/01-unit-economics.md), 실행 경로의 프롬프트 캐시가 어디서 깨지는지는 [08 · 프롬프트 캐시](docs/08-prompt-cache.md). 채점기가 400턴 내내 같은 지적을 반복한 원인이 캐릭터 카드의 자기모순이었던 건과, 그걸 LLM 없이 잡는 `npm run lint-cards`는 [09 · 카드 린트](docs/09-card-lint.md). 요약 기억이 어떤 사실을 떨어뜨리는지는 녹음 위에서 요약기만 다시 돌리는 `npm run memory-replay`로 1시간짜리 재실행 없이 본다(02, 03). 측정 자체의 신뢰도(채점기 노이즈 ±0.4, 시뮬레이터가 말하지 않은 사실의 프로브 제외, 규칙 보정)는 각 문서의 "한계" 절에 적었다. 캐릭터 하나와의 대화를 넘어 여러 캐릭터가 시간과 장소를 공유하고 유저가 없는 동안에도 세계가 움직이는 구조의 설계와 그 첫걸음(사실마다 출처)은 [10 · 살아 있는 세계](docs/10-living-world.md).

## 구조

```
characters/        캐릭터 카드 (YAML). 정체성은 언어 중립, 말투는 언어별 블록(ko/ja/en)으로 분리
packages/engine/   채팅 엔진: 프로바이더 추상화, 버전별 프롬프트 빌더(v1/v2/v3, 경계 변형), 장기 기억, 세션
packages/eval/     유저 시뮬레이터 → 대화 생성 → 채점(LLM + 규칙) → 리포트 / 재생성 사유 분류 / 안전 감사
  scenarios/       유저 대본: 비트, 흘릴 사실, 회상 프로브, fiction/real-risk 구간
  experiments/     실험 설정 (arm, 모델, 턴 수, 리플레이 소스)
docs/              실험별 1 Pager
scripts/           재현 가능한 계산 스크립트 (`npm run econ`)
apps/server, web   TypeScript API 서버(SSE) + React 데모                        (예정)
```

### 엔진 설계 원칙

- **정체성과 상태의 분리.** 카드의 `identity`/`world`/`hardConstraints`는 절대 바뀌지 않는 블록, `memory`는 매 턴 갱신되는 블록. 섞어 두면 긴 대화에서 설정이 흐려진다는 가설은 실험 1에서 확인됐다.
- **말투는 언어별 모듈.** `style.ko`, `style.ja`에 존댓말/경어 수준, 호칭, 1인칭, 말버릇, 금지 표현, 예시 대사를 따로 둔다. 언어가 늘 때 정체성은 건드리지 않는다(실험 5).
- **안전은 캐릭터 안에서.** `boundaries`는 "캐릭터를 유지한 채 걱정하고 도움을 권한다"처럼 그 캐릭터의 행동으로 쓴다. 범용 정책 블록과의 차이는 실험 4.
- **프롬프트는 버전이다.** `v1-flat`(평면), `v2-structured`(섹션 + 메모리 + few-shot), `v3-structured`(+ VARIETY: 반복 금지, 지문 길이), `v4-structured`(+ 에코 오프너·고정 마무리 금지), `v5-structured`(+ 아는 사실 하나씩 꺼내 쓰기), `v6-structured`(+ REGISTER: 문장 끝 경어 수준 고정, 질문 1개 이하, 감정은 행동으로), `v7`/`v8-structured`(+ VARIETY가 지워 버린 카드 습관 복원), `v9-structured`(+ MEMORY를 믿는 규칙: 유저가 이미 말한 사실을 처음처럼 꺼내도 기억한다고 답하고, 안 한 말은 귀속하지 않는다), `v10-structured`(+ 현재 시점은 유저가 권위: 200턴에서 v9가 유저의 요일을 네 번 고친 사건에서 나왔지만, 50턴에서 카엘이 유저의 틀린 주장까지 받아 보류), `v11-structured`(v10의 범위를 '지금 이 순간'으로 좁히고 과거 합의·세계 규칙·귀속된 말은 기억 쪽을 한 번만 지키게; 요일 정정 0, 대신 200턴 리플레이에서 "그런 말 한 기억이 없어요"류 답장이 8→18로 늘었다), `v12-structured`(귀속된 말은 걸린 것이 있을 때만 고치고 두 답장 연속으로는 고치지 않는다; 그 답장이 18→2로 줄었지만 400턴 프로브를 v10처럼 잃어 보류), `v13-structured`(v12 + "표현을 흘려보내는 것은 아는 것을 숨기는 게 아니다": 정정 답장 2, 400턴 프로브 복귀, 회상 7/7; **현재 기본값**), `v14-structured`(+ 사실의 출처로 말한다: 본 것·들은 것·네가 말한 것만 알고, 전해 들은 것은 전해 들은 것으로; 200턴에서 출처를 말하는 답장만 늘고 프로브·기억·정정 어느 것도 움직이지 않아 보류. 처음엔 기억 −0.55로 읽었지만 v13을 다시 생성하자 같은 폭으로 흔들려 노이즈로 정정), `v15-structured`(v14의 문장을 뒤집어 "기억의 사실은 전부 네게 닿은 것, 모르는 것은 기억에도 대화에도 없는 것만"; 처음 듣는 척은 사라졌지만 400턴 프로브를 v12처럼 잃어 보류. 출처 문장은 1:1에서 할 일이 없어 다른 캐릭터에게 들은 사실이 생기는 단계에서 다시 잰다, 실험 10), `v3-cached`(상태 블록을 컨텍스트 메시지로 분리, 실험 8), 경계 변형 `v2-no-boundaries` / `v2-strict-safety`. 평가 하네스가 버전 간 차이를 측정한다.
- **프로바이더 중립.** Claude(Claude Code CLI 경유), OpenAI, Ollama가 같은 인터페이스 뒤에 있다. 모델은 `provider:model` 스펙 문자열 하나로 바꾼다. 엔진, 서버, 평가가 모두 같은 `ChatSession`을 쓰므로 평가가 측정하는 것이 곧 유저가 받는 것이다.
- **장기 기억.** 최근 N턴은 그대로, 그 밖은 요약 + 사실 목록(≤25) + 관계 단계로 접어서 프롬프트에 넣는다. 창을 늘리는 것보다 싸고 정확하다(실험 2). 요약 프롬프트에는 화자 귀속 규칙과 고유명사 보존 규칙이 있다. 둘 다 200턴 실행에서 저장이 틀리거나 빠진 사례(화자 뒤바뀜, 동네 이름 탈락)에서 나왔고, 녹음 위에서 요약기만 다시 돌리는 `npm run memory-replay`로 수정 전후를 비교했다. 사실마다 출처(`user`/`self`/`witnessed`/`told`/`rumor`)가 붙는다(요약 규칙 v3, 기본값: 50턴 A/B에서 회상·사실 수·비용이 v2와 같았다). 그 출처로 말하게 하는 프롬프트 `v14`/`v15-structured`는 1:1 대화 200턴에서 v14는 얻은 것이 없고 v15는 400턴 프로브를 잃어 보류했다. 출처가 실제로 갈리는 다중 캐릭터 단계에서 다시 잰다(실험 10).
- **공유 세계(실험 10, 2단계).** 캐릭터가 유저와 대화하지 않는 시간에도 세계 안에 있다. 유한한 장소 목록, 하루 네 슬롯의 시계, 대화에서 추출한 할 일, 그리고 유일한 쓰기 지점인 사건 장부(`worlds/*.yaml`, `packages/engine/src/world/`). 하루를 넘기면 할 일이 호출 1회로 결정되어 장부에 적히고(같은 장소에 다른 주연이 있으면 둘의 장면 1회), 캐릭터에게는 `witnessed`/`told` 출처의 기억 사실로 들어간다. 첫 테스트(심부름, arm당 3대화): 장부를 받은 하루는 18답장 중 지어냄 0·회상 6/6, 장부 없는 하루는 "모른다"가 아니라 지어냈다(8/18). 하루 넘기기 비용 호출 1회, 프롬프트 +3%. 둘째 테스트(전언, 주연 둘): 하루가 책방에서 윤 사장과 만난 장면이 호출 1회로 결정되고 서로 말한 것만 `told`로 건너간다. 다음날 윤 사장은 본 것을 말하고, 들은 것은 "하루 씨가 그러던데"로 붙이고, 하루가 전하지 않은 유저의 비밀은 모른다(회상 9/9, 음성 프로브 6/6, 지어냄 1/30). 출처 문장 v14/v15는 여기서도 v13과 차이가 없었다. 셋째 테스트(소문, 주연 셋): 윤 사장이 저녁에 하루의 이모와 만나는 일과 장면이 세계가 스스로 돌린 첫 장면이고, 다음날 이모는 "윤 사장이 그러는데 하루가 그러더라"로 두 겹 출처를 붙여 말하며 이직 얘기는 모른다(회상 9/9, 음성 6/6, 지어냄 1/30). 두 번째 건너기에서 남는 세부는 장면이 무엇을 다뤘느냐에 따라 4/4에서 0/4까지 갈린다. 넷째 테스트(충돌): 유저가 심부름 슬롯에 캐릭터를 붙잡으면 심부름은 다음 날로 미뤄지고 캐릭터는 "어제는 민수 씨가 오래 계셨잖아요"라고 말한다(음성 3/3, 두 곳 동시 존재 0). 미룬 사실 하나에서 이모가 "그 시간에 카운터를 봐 주겠다"는 세부가 세계 안에서 생겨 유저에게 닿았다. 다섯째 테스트(상태 변화): 책방의 수도관이 터져 목요일까지 닫히는 사건이 장소 상태를 바꾸고, 하루는 그 소식을 이모에게 들어 "선영 씨한테 들었어요"로 말하며, 유저가 "오늘 목요일이죠?"라고 틀리면 "오늘은 수요일이에요. 목요일은 내일이고요"로 한 번 바로잡는다(회상 12/12, 음성 3/3). 실험 2에서 "현재는 유저의 것"으로 끝냈던 요일 문제가 세계 시계가 생기자 반대로 풀린다. 여섯째 테스트(긴 공백): 유저가 7일·30일·180일을 비우면 세계는 최근 7일만 하루씩 살고 그 앞은 30일 구간마다 한 번 결정하므로 반년이 일주일보다 호출 4회 비싸다. 돌아온 날 하루는 "반년이에요. 백팔십 일 지났어요"라고 세고, 반년 전의 심부름을 접힌 요약에서 반년 전 일로 말하며(회상 6/6, 음성 4/4, 지어냄 0/20), 윤은 같은 일을 목격자로 말한다. 긴 공백이 드러낸 결함 다섯(날짜 없는 사실, 구간 안의 심부름, 요약의 날짜 표기, 빈 장부 채우기, 세계가 유저의 물건을 처리함)을 네 번의 실행으로 닫았다. 일곱째 테스트(연쇄): 월요일의 단수 안내문이 화요일 카페의 "머신을 못 써 드립만"과 시장의 "두부 가게 휴업"을 낳고 수요일 저녁 복구로 끝난다(하루 상한 2, 목요일 아침 장소 상태 모두 평소). 안내문은 선영만 봤지만 호출 없이 소문으로 동네에 퍼지고, 하루는 목격자로, 윤은 "선영 씨가 그러는데"로 같은 사흘을 말한다(회상 15/16, 음성 8/8). 장면에 "전할 소식" 목록을 주는 arm은 아무것도 사지 않았다. 여덟째 테스트(주연 수): 같은 7일을 주연 1 / 2 / 3 / 5명으로 살면 호출은 11 / 9 / 14 / 16(하루 장면 상한이 잡는다), 토큰은 38k / 38k / 76k / 92k(장면이 싣는 "아는 것"의 길이가 올린다), 하루의 회상은 16/16. 세계가 출장 간 유저의 책을 "단골 손님"에게 건넨 실행이 하나 있어 세계와 장면에 유저가 돌아오는 날을 주도록 했다. 주연의 기준은 N이 아니라 "최근 7일 안에 유저가 말을 건 인물"로 둔다. 아홉째 테스트(유저 영향): 책방의 수도관이 유저가 맡겨 둔 책을 적시면, 하루는 인사만 받고도 "그보다 민수 씨, 책다락 소식이 있어요. 어제 선영 씨가 와서 얘기해 줬거든요"로 먼저 말하고 환불은 "윤 사장님이 정하실 일"로 멈추며, 윤은 주인으로서 "1권 표지가 젖어서 울었어요. 2권은 비닐에 싸여 멀쩡하고요"를 먼저 꺼내고 "속지는 마른 다음에 펴 봐야 알고요"에서 멈춘다(회상 12/12, 음성 6/6). 첫 실행에서는 소식이 소문으로 세부까지 실려 가 하루가 "저도 거기 있었어요"라고 했고, 소문은 사건만 싣고 세부는 목격자의 것으로 바꿨다. 아홉 번의 수정 뒤 첫째·셋째·다섯째 테스트를 같은 코드로 다시 돌려 회상과 음성이 그대로인 것을 확인했다(6/6·3/3, 9/9·6/6, 12/12·3/3). 그 중 한 실행은 시뮬레이터가 대화 중간에 "다음 날 아침"으로 건너뛰어 심부름이 추출되지 않은 채 빈 장부로 통과했고, 시뮬레이터에 "한 번의 만남, 시간을 건너뛰지 않는다"를 넣었다. 열째 테스트(주의): 유저가 일주일 비우기 직전에 "돌아왔을 때 유저에게 닿을 사람"을 호출 한 번으로 고르게 하면(상한 3만 규칙) 두 번 다 하루·책방 윤·조 반장을 고르고 선영·정 씨를 뺐다. "최근 7일 안에 말을 건 사람 + 심부름 보유자" 규칙은 하루만 남겨서 심부름이 윤 없이 결정되고, 돌아온 날 하루는 "수요일에 받아 왔어요", 윤은 "아직 여기 있어요"라고 한다. 한 인물씩 장부에 대고 재는 프로브는 둘 다 O를 줬으므로, 두 인물의 그날 대화를 나란히 읽고 모순을 보는 합치 검사를 채점에 넣었다(판단 2/2, 규칙 0/2, 전원 주연 2/2; 호출 15 / 15 / 20, 토큰 56k / 47k / 96k). 30일 공백을 여섯 번 더 돌려 여섯째 테스트에서 남겼던 "접힌 요약의 살 붙이기"가 소음이었음을 확인했고, 대신 접기가 윤의 목격을 보고서처럼 써서 윤이 "하루 씨가 온 건 못 봤어요"라고 하는 결함을 찾아(접힌 실행 0/2) 접기 프롬프트가 그 인물의 시점을 지키게 했다(접힘을 강제한 3실행 3/3).
- **프롬프트가 못 지키는 규칙은 엔진이.** "같은 말버릇을 연속으로 쓰지 않는다"는 세 라운드 동안 문구를 바꿔도 답장 다섯 중 하나에서 깨졌다. 카드에 오프너를 글자 그대로 적어 두면(`style.ko.openers`) 엔진이 연속 두 번째 오프너를 떼어 낸다(`filters.ts`, 재생성 없이 비용 0, 스트리밍은 첫 대사 줄까지 보류). 녹음에 드라이런하는 `npm run filter-replay`로 먼저 확인했다(2연속 14.5% → 0%).

## 시작하기

```bash
npm install
cp .env.example .env     # 기본값은 Claude Code CLI(구독) 경로. `claude`가 PATH에 있고 로그인돼 있으면 키 없이 동작
npm test

# 터미널 채팅
npm run chat -- --character haru --lang ko                              # claude-cli:sonnet, v13-structured
npm run chat -- --character kael --lang ja --model claude-cli:haiku --prompt v2-structured
npm run chat -- --character haru --lang ko --model openai:gpt-5-mini    # OPENAI_API_KEY 설정 시
npm run chat -- --character haru --lang ko --model ollama:qwen2.5:7b    # Ollama 설치 시
```

기본 LLM 경로는 Claude Code CLI(`claude -p`)다. API 키 대신 Claude 구독으로 돌리기 위한 선택이며, 프로세스 1개/호출(약 4~5초), 온도 조절 불가, 구독 사용량 윈도우 적용이라는 제약이 있다. 그래서 프로바이더 추상화가 있고, 스펙 문자열만 바꾸면 OpenAI나 로컬 모델로 같은 실험을 다시 돌릴 수 있다.

입력은 앱들과 같은 형식으로: `*행동과 지문*` `"대사"`. 채팅 중 명령: `/more` (캐릭터가 이어서), `/regen` (재생성), `/prompt`, `/memory`, `/quit`

## 평가

```bash
npm run eval -- all packages/eval/experiments/smoke.json --judge fake      # 오프라인 파이프라인 점검 (가짜 프로바이더)
npm run eval -- estimate packages/eval/experiments/prompt-version.json     # 실행 전 호출 수·토큰·비용

npm run eval -- all packages/eval/experiments/prompt-version.json          # 1  v1 vs v2 (sonnet, 50턴)
npm run eval -- all packages/eval/experiments/memory.json                  # 2  기억 3종 (prompt-version의 유저 턴 리플레이)
npm run eval -- all packages/eval/experiments/regen-fix.json               # 3  v2 vs v3 (리플레이)
npm run eval -- all packages/eval/experiments/safety.json                  # 4  경계 문구 3종 (self-replay)
npm run eval -- all packages/eval/experiments/haru-ja.json                 # 5  일본어 50턴
npm run eval -- all packages/eval/experiments/model-r1.json                # 6  sonnet vs haiku (리플레이)

npm run eval -- regen  eval-results/prompt-version                         # 재생성 사유 분류만 다시 (--rules-only: 규칙만 재계산)
npm run eval -- safety eval-results/safety                                 # 안전 감사만 다시
npm run eval -- judge  eval-results/model --format-only                    # 규칙 점수만 재계산, LLM 점수 재사용
```

- **시나리오** (`packages/eval/scenarios/*.yaml`): 유저 페르소나, 비트별 목표, 비트마다 자연스럽게 흘릴 사실(정답지), 특정 턴에 던지는 회상 질문(프로브), 안전 감사용 fiction/real-risk 구간.
- **시뮬레이터**: LLM이 유저를 연기한다. `replayFrom`으로 이전 실행의 유저 발화를 그대로 재사용하면 모든 arm이 같은 입력을 받는다. `replayArmId`가 arm 중 하나면 그 arm을 먼저 시뮬레이터로 돌리고 나머지가 리플레이한다.
- **채점**: 10답장마다 체크포인트. LLM 채점 3개(설정 일관성, 기억, 말투 준수, 1~5점) + 규칙 기반 포맷 검사 8개. 프로브는 정답과 대조해 회상률을 내되, 시뮬레이터가 그 사실을 실제로 말한 프로브만 분모에 넣는다.
- **재생성 사유 분류** (`regen`): 답장마다 규칙(형식, 길이, 유저 대신 서술, 언어 혼입, 문장 2개 이상 반복) + LLM(유저 말 무시, 캐릭터 이탈, 밋밋함, 구조 반복) 라벨. arm별 100답장당 빈도표가 "무엇을 먼저 고칠지"를 정한다.
- **안전 감사** (`safety`): 시나리오가 표시한 구간의 답장을 ok / over_refusal / under_reaction / violation으로 판정. 과잉 거부와 과소 반응을 따로 센다.
- **리포트**: arm별 평균과 표준편차, 체크포인트별 드리프트 곡선, 답장당 토큰(프롬프트·캐시·출력).

채점은 생성 모델보다 상위 모델(opus)로 둔다. haiku 채점기는 1턴에 밝힌 이름을 두고 "듣기 전에 불렀다"고 깎는 오판을 했다. 같은 대화를 opus가 세 번 채점하면 일관성은 ±0.4, 기억·말투는 ±0.2 안에서 흔들린다. 같은 프롬프트로 200턴을 다시 생성하면 기억은 ±0.45까지 흔들려서(실험 2 열 번째), 1대화의 평균 차이는 0.5 미만을 읽지 않고 프로브와 채점기 메모의 패턴으로 판정한다.

### 관측성 (Langfuse)

`LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY`가 있으면 모든 LLM 호출이 [Langfuse](https://langfuse.com) 트레이스로 남는다. 없으면 전부 no-op이라 평가와 채팅은 그대로 돈다. 로컬은 공식 `docker-compose.yml`로 self-host(`http://localhost:3000`), 키는 `.env.example` 참고.

| 단위 | 무엇이 남나 |
|---|---|
| 트레이스 | 대화 1개 (`eval:<scenario>/<arm>`, 채팅은 세션). 태그: 시나리오, arm, 프롬프트 버전, 리플레이/시뮬레이션 |
| generation | 호출 1개. role(character · simulator · memory · judge · regen · safety), 유저 턴, 모델, 입력 메시지, 출력, 토큰(입력 · 캐시 · 출력), 지연 |
| score | 채점 4지표 + 회상률, 재생성 사유별 100답장당 빈도, 안전 과잉 거부 · 과소 반응 · 위반율. 전부 그 대화의 트레이스에 붙는다 |

그래서 "일관성 3점 이하"나 "regen_repetition > 50"으로 트레이스를 걸러 그 답장을 만든 프롬프트 전문을 바로 읽을 수 있다. 평가 결과 JSON(`eval-results/`)은 그대로 남고, Langfuse는 그 위의 탐색 도구다.

### 비용 통제

| 장치 | 무엇 | 어디 |
|---|---|---|
| `estimate` | 역할별(캐릭터·시뮬레이터·기억·채점) 호출 수와 토큰, 정가 비용과 실제 청구 비용을 실행 전에 표로 출력 | `eval estimate <config>` |
| `maxUsd` | 청구 비용 누적이 상한을 넘으면 새 호출을 거부하고 진행 중 대화는 `truncated`로 저장 | 실험 설정 |
| `replayFrom` | 이전 실행의 유저 발화를 재사용. 시뮬레이터 비용 0, arm 간 분산 감소 | 실험 설정 |
| `claude-cli:<model>` | Claude Code CLI(`claude -p`)로 호출해 구독 한도에서 차감(청구 $0). 고정 오버헤드 830토큰(캐시됨) | 모든 모델 스펙 |
| 재시작 | `run`은 outDir에 이미 끝난 대화가 있으면 건너뛴다. 사용량 윈도우에 걸려 멈춰도 같은 명령으로 이어간다 (`--fresh`로 처음부터) | `eval run` |

실측: 50턴 대화 4개 생성(sonnet) 18분·432호출, opus 채점 40호출 100초. 가격표는 `packages/eval/src/pricing.ts` 한 곳.
